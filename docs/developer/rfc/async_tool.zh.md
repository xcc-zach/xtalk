# RFC：异步工具调用

* **作者**：刘展勋
* **状态**：Draft
* **日期**：2026.7.14

## 1. 背景

[这里](https://github.com/xcc-zach/xtalk/tree/feature/tool)有异步工具调用的第一版实现。用户可以向AI安排任务，并在此之后与AI对话，AI完成任务之后会将结果推送给用户。例如代码编写场景，用户委派给agent代码编写任务，Agent调用工具编写对应代码，同时用户可询问Agent代码相关的问题。后台代码编写任务能同步执行。详细文档见 https://github.com/xcc-zach/xtalk/blob/feature/tool/docs/docs/tool_design.zh.md。

## 2. 目标

本方案希望实现：

* 验证当前异步工具调用系统可行。
* 查看在不微调上游大语言模型的情况下，工具调用的性能。
* 准备异步工具调用的微调数据，并微调LLM。其中着重模型将思考委托给上游模型的能力。

## 3. 方案

### 验证异步工具调用系统

设计如下工具：
- 思考工具，输入问题，上游LLM进行思考，最终将结果返回。仿照GPT Live，在触发该工具时，模型可以回复”稍等，让我想一下“这样的话。
- 网络检索工具
- 深度研究工具deep research，内含网络检索能力与大型LLM，输入研究主题与描述，内部LLM检索并整合信息，并不断反馈研究进度，研究结束后进行最终汇报

对话系统模型选型：
- 参考https://github.com/xcc-zach/xtalk/blob/feature/tool/docs/tutorial/sample_config_for_fully_local_deployment.zh.md，仅部署本地ASR LLM TTS

### 性能查看

人工对话检查Qwen3-30B A3B 是否能完成好上述异步工具调用任务；根据主观感受总结不足。

### 数据准备与微调

未经微调的LLM性能不佳时，准备数据：

- 数据格式：抓取异步工具调用的LLM对话历史。数据需遵循该格式，包括工具调用、工具信息在对话历史中的位置，可用的辅助工具（例如用于订阅、取消订阅异步工具进度、关闭异步工具、显示异步工具进度的自带辅助工具）
- 数据构造：
    - 针对委派思考的工具微调
    - 通用异步工具微调

目标模型：30B量级及以下小模型；模型仅用作对话前端

## 4. 风险

- 开发过程中想到更多任务可以设计其他异步工具
- 辅助工具可能根据使用情况发生变化，需要重新设计方案
- 微调数据准备方案待进一步明确

## 5. 验收标准

* [ ] 实现上述几个异步工具
* [ ] 修复系统bug并验证系统可运行
* [ ] 总结不微调时系统不足
* [ ] 微调后模型
